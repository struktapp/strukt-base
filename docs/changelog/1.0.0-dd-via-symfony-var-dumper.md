# 1.0.0 — dd() delegates to symfony/var-dumper

**Date:** 2026-10-15

**Changed**

- Added a `symfony/var-dumper` requirement (`^7.0 || ^8.0`) to `composer.json`.
- Removed base's own `dd()` function and its `helper_add('dd')` registration;
  the `VarDumper` import was dropped from `src/helpers.php`.
- `dd()` and `dump()` are now provided globally by symfony/var-dumper. `dd()`
  renders each value with Symfony's VarDumper, tags extra arguments with their
  position, sends an HTTP 500 header when headers have not been sent, and exits
  with status 1.

**Why**

- `dd()` should render with Symfony's VarDumper instead of `var_dump()`.
- symfony/var-dumper already ships a global `dd()` (and `dump()`) in its
  autoloaded functions file, and Composer loads a dependency's files before the
  dependent package's files. That meant symfony's `dd()` was always defined
  first, so base's guarded `dd()` could never run. Depending on symfony and
  dropping base's dead duplicate is the only way to have a single, working
  `dd()`.

**Documentation**

- `README.md`: description and requirements updated; `dd()` is no longer listed
  as a base-declared helper, and the new "dd() and dump()" note records that
  symfony/var-dumper provides them. The helper inventory no longer lists `dd`.

**Tests**

- `tests/Unit/BaseTest.php`: dropped `dd` from the base registry expectations
  and added a test asserting `dd()`/`dump()`/`VarDumper` come from
  symfony/var-dumper and that `dd` is not registered in base's helper registry.

**Public API impact**

- New runtime dependency: `symfony/var-dumper`.
- Behaviour change: `dd()` now formats with Symfony's VarDumper (labelled
  multi-value dumps, an HTTP 500 header when applicable, and a bug glyph for no
  arguments) and no longer appears in `helper('base')`.
