# 1.0.0 — dd() gains a Symfony VarDumper fallback

**Date:** 2026-10-15

**Changed**

- Re-added a guarded `dd()` to `src/helpers.php`, implemented with
  `Symfony\Component\VarDumper\VarDumper::dump()` (followed by `exit(1)`), and
  restored the `VarDumper` import.
- The declaration is wrapped in `if (!function_exists('dd') && helper_add('dd'))`,
  so it is skipped whenever the global `dd()` already exists — which is the
  normal case, because symfony/var-dumper declares `dd()` first. In that case
  base registers nothing and `dd` stays out of `helper('base')`.

**Why**

- symfony/var-dumper declares `dump()`/`dd()` in
  `Resources/functions/dump.php`, a Composer file-autoload. Composer
  deduplicates file-autoloads by a package-scoped identifier,
  `md5("symfony/var-dumper:Resources/functions/dump.php")`. A globally
  installed PsySH phar bundles its own symfony/var-dumper and registers that
  identifier at boot without exposing the global `dd()`/`dump()`, so the
  project's `dump.php` is skipped and `dd()` ends up undefined. The guarded
  fallback keeps `dd()` available even when symfony's functions file is not
  loaded.
- This restores the previously removed base `dd()` (see
  `1.0.0-dd-via-symfony-var-dumper.md`), but as a fallback rather than a
  replacement: symfony's `dd()` still wins wherever it is loaded.

**Documentation**

- `README.md`: the "dd() and dump()" section now documents the guarded fallback,
  and the inventory note records that `dd` is registered only when the fallback
  defines it.

**Tests**

- `tests/Unit/BaseTest.php`: the existing `dd`/`dump` assertions continue to
  hold because the suite runs with symfony's functions file loaded (symfony's
  `dd()` wins and base's fallback is skipped). The test was renamed to
  "dd and dump resolve to symfony/var-dumper when its functions file loads".
  The fallback path (no symfony functions file) can only be exercised outside
  the Composer autoloader, so it is verified manually in PsySH.

**Public API impact**

- `dd()` remains available; base now declares a guarded fallback with the same
  `dd(mixed ...$values): never` signature. Behaviour is unchanged when
  symfony/var-dumper's global is present.
