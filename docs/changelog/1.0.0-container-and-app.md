# 1.0.0 — Dependency container and app() accessor moved into strukt/base

**Date:** 2026-10-15

**Changed**

- `Strukt\Framework\Container\Container`, `ContainerException`, and
  `NotFoundException` moved from `strukt/framework` into `strukt/base` as
  `Strukt\Container\Container`, `Strukt\Container\ContainerException`, and
  `Strukt\Container\NotFoundException`. The container is now a low-level
  primitive alongside `Strukt\Alias` and `Strukt\Helper`.
- `Container` gained `getInstance(): Container` and
  `setInstance(?Container $container): ?Container`, owning the process-wide
  shared instance. The framework `container()` helper now delegates to these
  instead of holding its own `static` singleton, so `app()` and `container()`
  return the same object.
- Added the `app()` helper: `app()` returns the shared container, `app($id)`
  resolves a binding or autowires a class, and `app($id, $parameters)` builds a
  class with named constructor overrides.
- `base` is now the single owner of the lowest-level primitives. `commons`
  stopped re-declaring `alias()`, `helper_add()`, `raise()`, `is_map()`,
  `notnull()`, and `negate()`, and dropped its duplicate `Strukt\Raise` class;
  those names resolve from `base`.
- Added a `psr/container` requirement (the interface the container implements).

**Why**

- `app()` and the container were only reachable from the top of the dependency
  graph (the framework). Moving them into the bottom-tier `base` package lets
  any package call `app()` and lets the lowest-level code depend on one shared
  container abstraction.
- `base` and `commons` both declared the same globals behind
  `function_exists()` guards with divergent semantics, so behaviour depended on
  Composer's file-autoload order. Consolidating ownership removes that hazard.

**Documentation**

- `README.md`: description and requirements updated; new `app()` helper section,
  new "Container API" section, and the helper inventory now lists `app`.

**Tests**

- `tests/Unit/ContainerTest.php`: relocated from the framework suite and added
  coverage for `app()` (shared container, binding resolution/autowiring, and
  named overrides). The existing container behaviour tests moved with the class.

**Public API impact**

- New classes: `Strukt\Container\Container`, `Strukt\Container\ContainerException`,
  `Strukt\Container\NotFoundException`.
- New functions: `Container::getInstance()`, `Container::setInstance()`,
  `app()`.
- New runtime dependency: `psr/container`.
- Breaking for anyone importing `Strukt\Framework\Container\*` from the
  framework; the classes now live under `Strukt\Container`.
